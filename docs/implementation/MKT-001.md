This document describes WHAT was implemented, maps it to the acceptance

## What was built

A TypeScript modular monolith (ADR-0010) on Node.js 24 with background
workers (ADR-0004 capability class: pooled workers first).

```text
src/
├── platform/                  shared kernel (contracts + replaceable adapters)
│   ├── config/                explicit, fail-fast env configuration
│   ├── errors/                typed error taxonomy (implementation-contract §24)
│   ├── ids/ clock/            UUIDv7 ids, injectable clock
│   ├── observability/         correlation (AsyncLocalStorage), structured
│   │                          append-only records, metrics, sinks
│   ├── db/                    Db port + PostgreSQL adapter + SQL migrations
│   ├── queue/                 durable job queue port + PostgreSQL adapter
│   ├── objects/               object-storage port + memory/fs adapters
│   └── http/                  router, §23 mutation pipeline, server,
│                              request-authentication port
├── modules/                   the 26 frozen module BOUNDARIES from
│                              spec/architecture.md §6 (public.ts + internal/;
│                              no business logic — business contracts arrive
│                              with their Work Items)
├── workers/                   worker host (claim/execute/CAS complete-fail,
│                              correlation restore, retry backoff, drain mode)
│   └── handlers.ts            platform sample handler (real work + artifact)
├── api/                       platform API routes (§23 pipeline, 202 for
│                              long-running operations)
├── composition-root.ts        the ONLY src/ place importing concrete adapters
└── entrypoints/               api.ts / worker.ts process roots
tools/arch-check/              static architecture checker (spec-parsed rules)
tests/unit|architecture|integration
```

Key mechanics:

- **Durable queue** (`platform_jobs`, `platform_job_attempts`): unique partial
  index on `(queue, handler_kind, idempotency_key)` is the duplicate fence
  (implementation-contract §8); claims use `FOR UPDATE SKIP LOCKED`;
  completion/failure use CAS on a `version` column; attempt history is
  append-oriented; terminal states (`succeeded`, `dead`) are immutable by
  database trigger; correlation identity is persisted on job and attempt rows.
- **Correlation propagation**: HTTP middleware accepts/generates
  `x-correlation-id` and runs the request inside a correlation context; job
  submission captures the correlation identity into the durable row; the
  worker restores it from the database (the boundary crossing is durable, not
  in-memory); every structured record carries it.
- **Observability**: append-only record contract with required fields
  (timestamp, level, event, correlation_id, causation_id, actor, module) plus
  runtime fields (job_id, worker_id, attempt, duration_ms, status, ...);
  secret-shaped keys are redacted; production sinks expose exactly `{ write }`
  — there is no read-back path, so observability structurally cannot be an
  execution-state authority.
- **API conventions** (implementation-contract §23): every mutation runs
  authenticate → resolve canonical owner → authorize → validate (strict, with
  forbidden authority fields) → derive server-authoritative fields → execute
  → emit material-mutation event → respond. Long-running operations return
  `202` + durable operation id + status link.
- **Static architecture checker**: the frozen module set and the dependency
  matrix are parsed at check time from `spec/architecture.md` §6,
  `spec/module-dependency-matrix.md` and `spec/module-dependency-v1.3.md`, so
  enforcement cannot drift from the frozen documents. 19 rules cover module
  boundaries, matrix directions, internal-access bans, adapter isolation
  (composition root only), `pg`-only-outside-domain, entrypoint boundaries,
  test boundaries and structure.

## Verification contract run (exact commands and exit codes)

```bash
npm ci
npm run lint              # exit 0
npm run typecheck         # exit 0  (tsc --noEmit, strict)
npm run arch:check        # exit 0  (26 frozen modules parsed from spec)
npm run test:unit         # exit 0  (108 tests)
npm run test:architecture # exit 0  (7 tests)
npm run test:integration  # exit 0  (11 tests; real PostgreSQL 18 server)
```

Integration tests boot a REAL embedded PostgreSQL 18 server (official
binaries via `embedded-postgres`). On hosts whose ICU differs from the
bundled binaries' ICU 60 linkage (e.g. Ubuntu 24.04), the harness downloads
libicu60 from the Ubuntu archive into `.test-deps/` once and sets
`LD_LIBRARY_PATH` (override with `MOS_TEST_ICU_LIB_DIR`). A missing
dependency fails the tests loudly — never a silent green.

## Environment limitations disclosed honestly

- The GitHub repository manifest (`spec/repository-manifest.json`) lists
  `spec/change-request-004.md` and `spec/preflight-v1.4.md`, which are absent
  from the repository. Not fixed here (frozen documents are not modified by
  implementation Work Items); flagged for the architect.
- `OBS-AC-01..02` are not defined in `spec/requirements.md`; the definitions
  in issue #4 (the Work Order) were used verbatim, as instructed.
- `/deployments` has no entry in the frozen dependency matrix; the checker
  encodes it with an EMPTY allowance list (nothing inferred —
  `spec/module-dependency-v1.3.md` governs until an explicit addendum).
- Authentication is deliberately NOT user identity: only an internal
  service-token authenticator (fail-closed) exists as the pipeline STEP.
  User identity/tenancy arrive with MKT-002..004, per the issue's security
  contract ("establish the boundary conventions… do not create a bypass").
- Metrics are an in-process registry (OBS-001 plumbing); exposition/scraping
  endpoints are deployment-scope work (MKT-033).
- No Redis is used: PostgreSQL alone backs the durable queue, matching the
  architecture-lock requirement that recovery must never depend on Redis as
  authority (DEPLOY-AC-02 direction). The queue port remains replaceable.
